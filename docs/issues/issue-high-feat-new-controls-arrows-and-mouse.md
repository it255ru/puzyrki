# Новое управление: стрелки для первого игрока, мышь для второго, выбор способа в начале игры

- **Важность:** high
- **Тип:** feature (пересмотр решения [п. 9](../decisions.md))
- **Статус:** done (PR feat/new-controls)
- **Заказчик:** владелец проекта (2026-10-20)

## Требование
1. **Клавиатура (стрелки).** Влево / вправо — движение, **вверх — выстрел**. Других клавиш движения и стрельбы нет (A/D, Space, Enter, Ctrl убираются).
2. **Мышь.** Левая кнопка — выстрел, **смещение мыши влево/вправо — движение**. Управление только мышью, без клавиатуры.
3. **Выбор в начале игры:** на титульном экране игрок выбирает способ управления (клавиатура / мышь) и затем «играть вдвоём?». Второй игрок всегда управляется мышью, поэтому в игре вдвоём первый — только с клавиатурой.

## Уточнения (ответы владельца)
- **Меню старта — «способ + число игроков»:**
  1. Шаг 1: «Управление: Клавиатура (стрелки) / Мышь» — для первого игрока.
  2. Шаг 2: «Играть вдвоём? Да / Нет».
  3. Если выбрано «Мышь» и затем «Да», первый игрок автоматически переключается на клавиатуру (второй берёт мышь); меню показывает пояснение «В игре вдвоём: игрок 1 — стрелки, игрок 2 — мышь».
  4. Меню работает и с клавиатурой (↑/↓ и Enter), и с мышью (наведение и клик).
- **Мышь — смещение с захватом курсора (Pointer Lock):** курсор скрыт и захвачен, игрок двигается на величину смещения (`movementX`), а не следует за позицией курсора.

## Проектные решения (предлагаются, подтвердить при реализации)
- **Схемы управления отвязываются от номера игрока.** У игрока поле `control: "keyboard" | "mouse"`; `readInput(player)` читает свою схему. Цвет, метка и жизни остаются по номеру игрока.
- **Чувствительность:** `MOUSE_SENSITIVITY` (по умолчанию 1: один логический пиксель поля на один пиксель смещения с поправкой на масштаб канваса). Движение за шаг ограничено максимумом (чтобы резкий взмах мыши не телепортировал игрока): `MOUSE_MAX_STEP`.
- **Захват курсора:** запрашивается кликом в меню («Начать»). Если захват потерян (Esc, Alt-Tab, `pointerlockchange`) — игра на паузе, на экране «Кликните, чтобы продолжить»; клик снова захватывает и снимает паузу. Если Pointer Lock недоступен/отклонён — понятное сообщение, выбор клавиатуры остаётся доступен.
- **Подключение второго игрока в игре:** принято решение **не подключать** во время игры — только через меню (случайный клик по окну иначе добавлял бы игрока и захватывал курсор). Горячее подключение удалено.
- **Служебные клавиши без изменений:** Esc / P — пауза, Enter / R — рестарт на экранах конца игры, F2 / PageUp / PageDown — отладка. Так как Enter больше не кнопка выстрела, баг [рестарт Enter добавляет игрока](issue-medium-restart-with-enter-adds-second-player.md) устраняется самой схемой (проверить тестом).
- Правая кнопка и колесо мыши игнорируются, контекстное меню на канвасе отключено.
- Подсказки по управлению на титульном экране и в меню паузы обновляются; `docs/gameplay.md` и `docs/architecture.md` — тоже.

## Что затрагивает
`controls`, `readInput`, `Player.update`, `hotJoin`, титульный экран (`updateTitle`/`drawTitle` → меню), обработчики событий (мышь, `pointerlockchange`), `startGame(playerCount)` → `startGame(config)`, пауза при потере захвата, тесты (`04`, `06`, `05`), `harness.js` (заглушки мыши и Pointer Lock).

## Тесты (новые)
- Клавиатура: ←/→ двигают, ↑ стреляет; A/D, Space, Enter не действуют.
- Мышь: смещение двигает ровно на `movementX · чувствительность / масштаб`, клик стреляет, правая кнопка и колесо игнорируются, большой рывок ограничен, движение без захвата игнорируется.
- Меню: путь «клавиатура → один», «мышь → один», «клавиатура → вдвоём», «мышь → вдвоём» (первый автоматически клавиатура, второй мышь); навигация клавишами и мышью; повторное меню после рестарта не нужно (конфигурация сохраняется).
- Pointer Lock: запрос по клику; потеря захвата ставит паузу; клик возобновляет; ошибка/отсутствие поддержки показывает сообщение.
- Подключение игрока 2 кликом; рестарт Enter не подключает второго игрока.
- Два игрока: клавиатурный и мышиный ввод не влияют друг на друга.
- Регрессия: жизни, неуязвимость, гарпуны, шипы работают одинаково для обеих схем.

## Порядок
Делается до очков ([F3](issue-medium-feat-scoring.md)): ввод влияет на титульный экран, подсказки и тесты, которые иначе придётся переписывать дважды. Закрывает [баг с рестартом по Enter](issue-medium-restart-with-enter-adds-second-player.md).
