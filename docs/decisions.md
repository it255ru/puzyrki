# Решения и варианты

Принятые решения (владелец проекта):

- Игра называется «Пузырьки», репозиторий `it255ru/puzyrki` публичный (решение п. 13).
- Ветвление — trunk-based (`main` + короткие ветки).
- Игра — один файл `index.html`; доп. ресурсы из `assets/` (картинки, звуки).
- Хостинг — GitHub Pages.
- После каждой правки — тесты и проверка всех функций.
- До 2 игроков на одном устройстве.

Ниже — вопросы с вариантами. Статус **принято** означает, что владелец выбрал вариант, и по нему заведён issue.

## 1. Физика шара и подбрасывание при попадании
**Статус: принято: A → [issue](issues/issue-medium-feat-hit-impulse-physics.md)**

Сейчас: прыжок фиксированной высоты (`bs`), энергия не сохраняется, импульс от попадания пропал бы при первом касании пола.
- **A (рекомендую).** Нормальная физика: гравитация + отскок с коэффициентом 1.0 от пола; попадание добавляет шару вертикальную скорость вверх. Высота подбора хорошо предсказуема.
- B. Оставить `bs`, а при попадании временно повышать `bs` до следующего касания пола. Проще, но менее естественно.
- C. Дискретные «ступени» высоты по размерам, как в оригинале Pang (каждый размер имеет фиксированную высоту отскока, попадание поднимает на ступень).
Нужно подобрать импульс так, чтобы шары всех размеров могли достичь потолка при серии попаданий; для размера 6 — отдельно ([issue](issues/issue-low-biggest-ball-exits-top.md)).

## 2. Гарпун и потолок с шипами
**Статус: принято: B → [issue](issues/issue-medium-feat-spike-ceiling-sticky-harpoon.md)**

- **A (рекомендую).** Гарпун долетает до шипов и исчезает (как сейчас), шипы — часть потолка; гарпун не «прилипает». Просто, предсказуемо.
- B. Гарпун прилипает к потолку на ~0,5 с (как в оригинале): можно поймать шар, но требует новой стадии жизни гарпуна.
- C. Пробивающий гарпун как бонус (`maxHits`).

## 3. Правило «шар лопается о шипы, а не дробится»
**Статус: принято: A → [issue](issues/issue-medium-feat-spike-ceiling-sticky-harpoon.md)**

- **A (рекомендую).** Любой шар, чей верх коснулся шипов, лопается без осколков. Попадание гарпуном, при котором осколки сразу оказываются в зоне шипов, лопает оба осколка, потому что они касаются шипов.
- B. Шары у шипов лопаются только если попадание было по ним, а осколки уходят вниз.
Тесты: шар размера 3 на высоте шипов — лопается; шар размера 3 ниже — делится на два.

## 4. Очки и комбо
**Статус: принято: A → [issue](issues/issue-medium-feat-scoring.md)**

- **A (рекомендую).** Очки за размер шара + бонус за лопнувший у шипов целиком (поощряет мастерство) + комбо за серию без промахов; рекорд в `localStorage`.
- B. Только рекорд по времени прохождения.
- C. Без очков (текущее состояние).

## 5. Жизни
**Статус: принято: A → [issue](issues/issue-medium-feat-per-player-lives.md)**

- **A (рекомендую).** Раздельные жизни и неуязвимость у каждого игрока; потерявший все выбывает, второй продолжает; уровень перезапускается, только когда выбыли оба.
- B. Общий пул жизней (как сейчас) — проще, но один зевок наказывает обоих.

## 6. Уровни и сложность
**Статус: принято: A → [issue](issues/issue-medium-feat-level-data-and-campaign.md)**

- **A (рекомендую).** Описывать уровни данными (`{size, x, y, dx, color}` + возможные шипы), 10–15 уровней с нарастанием; первые 3 — обучающие (подбрасывание, шипы).
- B. Генератор уровней. Дольше в отладке, хуже управляется баланс.
Зависит от п. 1: баланс подбирать после выбора физики и фиксированного шага.

- **A (рекомендую).** Пока без лицензии (все права за вами), репозиторий приватный.
- B. MIT, когда решите публиковать.
- C. Не-коммерческая (CC BY-NC) для ассетов отдельно.

## 8. Название и ассеты
**Статус: принято → [issue](issues/issue-low-docs-license-and-assets-policy.md)**

«Пузырьки» — слово общего употребления, риска нет. Графику и звуки рисовать самим или брать с CC0 (kenney.nl, opengameart.org); не копировать ассеты Pang/Bubble Bobble. Это снимает вопрос об оригинальности.

## 9. Клавиши двух игроков и подключение второго
**Статус: принято: A → [issue](issues/issue-medium-feat-two-player-controls.md)**

- **A (рекомендую).** Игрок 1: A/D + пробел (по `e.code`: KeyA/KeyD/Space). Игрок 2: ←/→ + Enter (или правый Ctrl). Подключение второго — нажатие его «выстрела» на экране старта, без Shift-клавиш.
- B. Игрок 1: A/D + Shift; игрок 2: ←/→ + `/`.
- C. Игрок 1 на клавиатуре, игрок 2 — геймпад (Gamepad API).
Вместе с [issue про раскладку](issues/issue-high-keyboard-layout-dependent.md) и [Shift-клавиши](issues/issue-medium-shifted-keys-trigger-shoot.md).

## 10. Звук
**Статус: принято → [issue](issues/issue-low-feat-sound.md)**

Автозапуск звука блокируется браузером до первого нажатия — запускать `AudioContext` по первому нажатию клавиши (экран «Нажмите любую клавишу»). Короткие эффекты (выстрел, лопание, потеря жизни) — WAV/OGG в `assets/sounds/`, музыка — по желанию. Добавить кнопку выключения звука (клавиша M).

## 11. Цвета игроков
**Статус: принято → [issue](issues/issue-low-feat-player-colors-and-labels.md)**

Сейчас зелёный/синий/оранжевый/красный. Для двоих: синий и оранжевый (хорошо различаются при дальтонизме). Добавить форму/метку (номер «1»/«2» над игроком).

## 12. Браузерное тестирование
**Статус: принято: A → [issue](issues/issue-medium-feat-browser-smoke-test.md)**

Node-тесты с заглушками не проверяют реальную отрисовку.
- **A (рекомендую).** Добавить Playwright smoke-тест (запуск `index.html`, нажатие клавиш, снимок канваса) в CI. Одна дополнительная dev-зависимость.
- B. Ручной чек-лист перед каждым PR (`docs/checklist.md`).
- C. Оставить только Node-тесты.

## 13. Публикация через GitHub Pages
**Статус: принято: B — репозиторий публичный, Pages включён (https://it255ru.github.io/puzyrki/)**

Pages для приватных репозиториев требует платный план GitHub; на бесплатном репозиторий должен быть публичным.
- **A (рекомендую).** Разрабатывать приватно, workflow `pages.yml` уже есть (запуск вручную). Когда готовы публиковать — перейти на платный план или открыть репозиторий.
- B. Сразу публичный репозиторий.
- C. Держать приватным и публиковать собранную копию в отдельный публичный репозиторий `puzyrki-web`.

## 14. Новое управление (изменение решения п. 9)
**Статус: принято владельцем 2026-10-20 → [issue](issues/issue-high-feat-new-controls-arrows-and-mouse.md)**

Решение п. 9 (игрок 1: A/D + пробел; игрок 2: стрелки + Enter) **заменено**:
- Игрок с клавиатурой: стрелки ←/→ — движение, ↑ — выстрел.
- Игрок с мышью: левая кнопка — выстрел, смещение влево/вправо — движение (Pointer Lock, захват курсора).
- Второй игрок всегда с мышью; способ управления выбирается в меню в начале игры («способ + число игроков»).
- Подключение второго игрока в игре и кнопка выстрела на титульном экране из п. 9 больше не используются; второй игрок выбирается только в меню старта.
